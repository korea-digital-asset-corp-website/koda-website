# 테크블로그 글쓰기 가이드 (저자용)

노션에 글을 쓰면 Claude Code가 홈페이지 글로 바꿔 올려준다. 에디터도 CMS도 없다 — **노션이 원고, 코드가 게시본**이다. 이 문서는 글을 쓰는 사람이 알아야 할 것만 담았다. Claude가 따르는 변환 규칙의 정본은 `blog-post-workflow.md`다.

## 한눈에 보는 흐름

```
① 노션에 쓴다  →  ② Claude Code에서 /blog-post <노션 URL>  →  ③ PR(dev)·프리뷰 확인  →  ④ dev 머지  →  ⑤ main 릴리스
    (저자)                 (저자, 5분)                          (저자·리뷰어)          (리뷰어)       (릴리스 담당)
```

글 한 편이 코드 3곳에 들어간다. 모두 Claude가 만든다.

| 파일                                        | 역할                             |
| ------------------------------------------- | -------------------------------- |
| `src/components/blog/posts/<PascalCase>.tsx` | 본문 (노션 블록을 1:1로 옮긴 것) |
| `src/data/blogPosts.ts`                      | 제목·요약·카테고리·저자·날짜·썸네일 |
| `src/data/blogContentMap.tsx`                | 주소(slug) ↔ 본문 연결           |

## 사전 준비 (처음 한 번)

1. `koda-website` 레포를 clone하고 `npm install`. 브랜치 push 권한이 있어야 한다(없으면 관리자에게 write 권한 요청).
2. Claude Code 설치, `gh auth login` 완료.
3. **koda-dev MCP** 연결 — Claude가 노션을 읽고 PR을 만드는 통로다. Claude Code에서 `/mcp`를 쳤을 때 `koda-dev`가 connected면 된다. (설치는 팀 온보딩 문서 참조)
4. 레포 루트에서 Claude Code를 연다. `.claude/skills/blog-post`가 있는 레포라야 `/blog-post`가 뜬다.

## ① 노션에 쓰기

### 페이지 위치

kodax 워크스페이스 안이면 어디든 된다. 페이지 하나가 글 하나다. 공개(Publish to web)할 필요 없다.

### 맨 위에 메타 블록을 둔다

노션 API는 **페이지 제목을 돌려주지 않는다.** 그래서 제목을 포함한 메타 정보를 본문 맨 위에 콜아웃 하나로 적는다. 이 블록은 본문으로 옮겨지지 않고 메타 등록에만 쓰인다.

```
제목: 규제 읽는 블록체인 메이커 #1: 내 코인을 내 지갑으로 보내는데 왜 증빙이 필요할까?
카테고리: Insight
요약: 2026년 전면 개정된 트래블룰의 핵심을 정리하고, 소유권과 트래블룰이 별개의 축이라는 관점에서 커스터디 시나리오를 검증한다.
저자: 김주형 · Software Engineer
썸네일: 첫 번째 이미지        ← 선택. 없으면 생략
```

- **카테고리**는 셋 중 하나 — `Security` / `Engineering` / `Insight`.
- **요약**은 1~2문장. 목록 카드, 검색 결과, 카카오톡·슬랙 공유 카드에 그대로 나간다.
- **썸네일**은 "첫 번째 이미지" 또는 본문 이미지의 파일명. 없으면 목록에서 카테고리 워드마크가 대신 나온다.
- 날짜는 등록한 날이 자동으로 들어간다. 다른 날짜를 원하면 `날짜: 2026.09.01`을 추가한다.

### 쓸 수 있는 블록 → 사이트에서 이렇게 보인다

| 노션에서              | 사이트에서                                                   | 메모                                              |
| --------------------- | ------------------------------------------------------------ | ------------------------------------------------- |
| 제목2 (`/h2`)         | 큰 절 제목. **오른쪽 목차(TOC)의 항목**이 된다               | 글의 뼈대. 3~6개가 적당                           |
| 제목3 (`/h3`)         | 소절 제목. TOC에 들여쓰기로 표시                             | 제목1(`/h1`)은 쓰지 않는다 — 글 제목이 h1이다     |
| 문단                  | 본문                                                         |                                                   |
| 굵게                  | **굵게**                                                     |                                                   |
| 기울임 / 형광펜       | 색·굵기로 강조 (기울임 아님)                                 | 한글 이탤릭은 글자가 겹쳐서 색 강조로 바꿔 렌더  |
| 인라인 코드           | `코드`                                                       |                                                   |
| 코드 블록             | 언어 라벨이 붙은 코드 박스                                   | 언어를 지정한다. `Plain text`면 라벨 없이 나옴    |
| 이미지                | 본문 폭에 맞춘 이미지 + 캡션                                 | 아래 이미지 규칙 참고                             |
| 인용 (`/quote`)       | 왼쪽 초록 선이 있는 인용문                                   |                                                   |
| 콜아웃 (`/callout`)   | 연한 초록 박스                                               | 아이콘은 표시되지 않는다                          |
| 글머리 기호 / 번호 목록 | 목록                                                       | 한 단계만. 중첩 목록은 풀어서 쓴다               |
| 표                    | 표 (모바일에서는 가로 스크롤)                                | 4열 이하 권장. 첫 행을 헤더로 지정               |
| 링크                  | 초록 밑줄 링크, 새 창                                        |                                                   |
| 구분선 (`---`)        | 생략됨                                                       | 절 경계는 제목2가 만든다                          |

### 변환되지 않는 것 (쓰지 않는다)

토글, 데이터베이스(표 뷰·보드 등), 임베드(유튜브·트위터·Figma), 북마크 카드, 컬럼(2단 레이아웃), 동기화 블록, 수식, 다른 페이지 링크/멘션, 파일 첨부, 글자색·배경색·밑줄(형광펜 제외).

이런 블록이 있으면 Claude가 변환을 멈추고 어떻게 할지 묻는다. 유튜브 영상은 링크로, 2단 레이아웃은 위아래로 풀어서 쓴다.

### 서식에서 주의할 것

- 노션 서식 단축키(`Cmd+B`)를 쓴다. **마크다운 별표를 글자로 입력하지 않는다** — `**임치**`처럼 타이핑하면 별표가 그대로 본문에 남는다. 붙여넣기 후엔 한 번 훑어본다.
- 따옴표는 `"` `'` 그대로 쓰면 된다. 변환 시 곡선 따옴표로 바뀐다.
- 본문은 **한국어**다. 영어 페이지(`/en/blog`)에서도 같은 본문이 나온다. 영어 번역본은 지원하지 않는다.
- 내용은 노션에 쓴 그대로 옮겨진다 — Claude는 문장을 다듬거나 요약하지 않는다. 오타도 그대로 간다.

### 이미지 규칙

- PNG 또는 JPG. 본문 폭이 700px이라 **가로 1400px 이상**이면 고해상도 화면에서도 선명하다. 스크린샷은 원본 그대로 넣으면 된다.
- 노션 이미지 아래 캡션을 쓰면 사이트에도 캡션으로 나온다.
- 이미지는 변환 시 `public/assets/images/blog/`로 내려받아 레포에 함께 커밋된다. 노션 이미지 링크가 1시간 뒤 만료되는 건 신경 쓰지 않아도 된다.
- 썸네일로 쓸 이미지는 **가로형(2:1 정도)**이 히어로 카드에 가장 잘 맞는다. 세로형은 여백이 크게 남는다.

### 글 구조 팁

- 도입부는 제목2 없이 문단·콜아웃으로 시작해도 된다.
- 제목2 아래에 제목3를 두는 2단계까지만. 제목3 밑에 다시 제목3는 TOC에서 구분이 안 된다.
- 하단에 "참고 자료" 같은 절을 두려면 굵은 문단 + 목록으로 쓴다(제목2로 만들면 TOC에 잡힌다 — 원하면 제목2로).

## ② 변환 실행

레포 루트에서 Claude Code를 열고:

```
/blog-post https://app.notion.com/p/kodax/...
```

Claude가 하는 일 (보통 3~5분):

1. 노션 페이지를 읽고 이미지를 내려받는다.
2. 본문 컴포넌트를 만들고 메타를 등록한다.
3. `npm run lint && npm run build`로 검증한다.
4. `feat/blog-post-<slug>` 브랜치에 커밋·푸시하고 **dev 베이스 PR**을 만든다.

메타 블록이 없거나 빠진 항목이 있으면 중간에 묻는다. 대응표에 없는 블록이 있으면 처리 방법을 묻는다.

끝나면 PR 링크를 준다. 로컬에서 먼저 보고 싶으면 `npm run dev` → `http://localhost:3000/blog/<slug>`.

## ③ 프리뷰 확인

PR이 열리면 Netlify가 프리뷰를 만든다. PR 체크의 `netlify/kodax-website-dev/deploy-preview` → Details 링크, 또는 `https://deploy-preview-<PR번호>--kodax-website-dev.netlify.app/blog/<slug>`.

확인할 것:

- [ ] 목록 페이지(`/blog`)에서 맨 앞 히어로로 뜨는지, 제목·요약·카테고리·저자가 맞는지
- [ ] 오른쪽 목차(TOC)가 의도한 절 구조인지 (1024px 이상 화면에서만 보임. 모바일은 TOC 없음)
- [ ] 표가 잘리지 않는지, 이미지가 선명한지, 캡션이 붙었는지
- [ ] 강조(굵게·형광펜)가 의도한 자리에 있는지
- [ ] 슬랙에 프리뷰 링크를 붙여 공유 카드(제목·요약·이미지)가 제대로 나오는지

### 고칠 게 있으면

- **내용 수정** — 노션을 고치고 같은 Claude 세션에서 "노션 다시 읽어서 반영해줘". 본문 컴포넌트를 다시 만들어 같은 PR에 커밋한다.
- **메타(제목·요약 등) 수정** — 노션 메타 블록을 고치고 다시 실행하거나, Claude에게 "제목을 ○○로 바꿔줘".
- 노션을 고쳐도 **사이트는 자동으로 바뀌지 않는다.** 항상 다시 실행해야 한다.

## ④ ⑤ 게시

- 리뷰가 끝나면 PR을 **dev에 머지**한다 → `kodax-website-dev.netlify.app`에 올라간다.
- 운영 사이트(`kodax.com`) 반영은 **dev → main 릴리스 PR**로 한다. 릴리스 담당자에게 알린다. 글 하나 때문에 바로 릴리스할지, 다음 릴리스에 묶을지는 그때 정한다.
- 게시된 글을 고칠 때도 같은 흐름이다: 노션 수정 → `/blog-post` 다시 실행 → PR.

## 사이트에서 글이 어떻게 보이나

- **목록** (`/blog`) — 가장 최근 글이 상단 히어로, 나머지는 3열 카드. 스크롤하면 계속 로드된다.
- **상세** (`/blog/<slug>`) — 본문 폭 700px(토스 기술블로그 정도). 오른쪽에 목차, 하단에 공유 버튼(링크 복사·X·페이스북·링크드인)과 관련 글 2편(같은 카테고리 우선).
- **공유 카드** — 제목·요약·썸네일(없으면 KODA 기본 이미지)이 OG 메타로 나간다. 검색엔진용 구조화 데이터(BlogPosting)도 자동으로 들어간다.
- **주소** — `slug`는 제목의 영문 kebab-case. Claude가 정하고, 한 번 게시되면 바꾸지 않는다(링크가 깨진다). 원하는 slug가 있으면 메타 블록에 `slug: my-post`를 적는다.

## 자주 묻는 것

**저자를 두 명 적을 수 있나?** — 지금은 한 명이다. 공동 저자는 본문 첫 문단에 적는다.

**시리즈물은?** — 제목에 `#1`, `#2`를 붙이는 방식으로 한다. 시리즈 묶음 페이지는 아직 없다.

**노션 페이지를 나중에 지워도 되나?** — 게시 후에는 코드가 원본이라 지워도 사이트는 그대로다. 다만 수정할 때 노션에서 다시 시작하는 게 편하니 남겨두는 걸 권한다.

**변환 결과 예시가 보고 싶다.** — `src/components/blog/posts/KodaCustodyCoreArchitecture.tsx`(이미지·코드·표 포함)와 `TravelRule2026Custody.tsx`(브랜치 `feat/blog-post-travel-rule-2026-custody`, 콜아웃·표·참고 링크 포함)를 본다.
